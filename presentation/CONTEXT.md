# 바이브 코딩 전파 세미나

멀티캠퍼스 「바이브코딩으로 완성하는 풀스택 서비스」 교육 내용을 회사 동료에게 전달하는 발표의 용어집이다. 발표 자료와 발표 중 말하는 용어는 여기 정의된 이름을 따른다. Claude Code 관련 용어는 영문 그대로 쓴다.

## 발표 자체

**전파 세미나**:
외부 교육을 들은 사람이 그 내용을 사내 동료에게 다시 전달하는 발표.
_Avoid_: 교육, 강의, 워크숍

**청중**:
Claude를 이미 쓰고 있지만 CLAUDE.md·Skill·Hook·Harness 같은 Claude Code 용어에는 익숙하지 않은 회사 백엔드 개발자 약 20명.
_Avoid_: 수강생, 학생

**원자료**:
`VIBE_CODING/` 폴더의 강의자료 01_Vibe Coding 개요 ~ 08_배포, 총 8개 PDF. 발표 내용의 기본 출처이며, Harness 개념과 현재 공식 문서 기준의 사실 정정만 예외로 원자료 밖에서 가져온다.
_Avoid_: 교안, 참고자료 (추가_*.pdf, 채팅 기록 등은 원자료가 아니다)

**PRESENTATION-SPEC.md**:
덱의 설계서로, 전체 슬라이드 흐름과 슬라이드별 제목·핵심 메시지·핵심 내용·시각자료·발표자 노트를 적은 문서. 덱은 이 문서를 기준으로 만든다.
_Avoid_: 뼈대, 기획안, 슬라이드 목록

**SCRIPT.md**:
발표자가 슬라이드별로 실제로 말할 내용과 설명을 적은 발표 대본. 슬라이드에 보이는 내용이 아니라 말로 전달할 내용이다.
_Avoid_: 발표 원고, 멘트

**교육 이후 변경**:
원자료의 내용이 현재 Claude Code 공식 정보와 달라, 발표에서 현재 기준으로 고쳐 전달하는 항목.
_Avoid_: 오류, 수정사항

## Vibe Coding

**Vibe Coding**:
자연어로 AI와 대화하며 코드를 만들게 하고, 사람은 방향 제시와 결과 판단을 맡는 개발 방식 전반.
_Avoid_: 바이브 코딩(슬라이드 표기), AI 코딩, 프롬프트 코딩

**카파시식 Vibe Coding**:
안드레 카파시가 처음 말한 원래 형태로, 코드를 세세히 읽지 않고 AI 제안을 그대로 받아들이며 직감으로 반복하는 방식. Vibe Coding의 출발점이자 한쪽 끝이다.
_Avoid_: 순수 바이브 코딩

## Claude Code 구성 요소

**Harness**:
Claude 모델을 감싸서 도구 실행·권한·CLAUDE.md·Skill·Hook·MCP 등을 붙여 주는 실행 환경. Claude Code가 곧 Harness다.
_Avoid_: 하네스, 프레임워크, 래퍼

**CLAUDE.md**:
사람이 직접 써 두는 프로젝트 규칙과 맥락 파일로, Claude Code가 세션을 시작할 때마다 자동으로 읽는다.
_Avoid_: 메모리, 프로젝트 메모리, 지침 파일

**Auto memory**:
Claude가 대화 중 배운 내용을 스스로 적어 두는 기록으로, 다음 세션에 다시 읽힌다.
_Avoid_: 자동 메모리, 메모리(단독 사용)

**Subagent**:
독립된 Context에서 특정 유형의 작업만 맡아 처리하는 전문 에이전트로, `.claude/agents/`의 md 파일로 정의한다.
_Avoid_: 서브에이전트, 에이전트(단독 사용), 봇

**Skill**:
평소에는 이름과 설명만 로드되고 필요할 때 전체 내용을 로드하는 작업 단위 지침 묶음(SKILL.md와 스크립트).
_Avoid_: 스킬, 사용자 정의 슬래시 명령어 (Skill로 대체되어 deprecated)

**MCP**:
AI 모델이 외부 도구·서비스(DB, GitHub, 브라우저 등)를 호출할 수 있게 하는 표준 프로토콜.
_Avoid_: Plugin (별개 개념)

**Hook**:
Claude Code 생명주기 이벤트(도구 호출 전후, 응답 완료 등)에 맞춰 자동 실행되는 사용자 정의 동작.
_Avoid_: 훅, 트리거, 자동화 스크립트

**Plugin**:
Slash command·Subagent·Hook·MCP·Skill을 한 번에 설치할 수 있게 묶은 패키지.
_Avoid_: 플러그인

**Plan mode**:
Claude가 분석과 계획만 하고 파일 수정이나 명령 실행은 하지 않는 권한 모드.
_Avoid_: 플랜 모드, 계획 모드

**Context**:
한 세션에서 모델이 한 번에 볼 수 있는 대화·파일·지침의 전체 분량.
_Avoid_: 컨텍스트, 맥락(용어로 쓸 때)

## 개발 흐름

**검수 루프**:
생성 → 평가 → 개선 → 재생성을 품질 기준에 도달할 때까지 반복하는 AI 결과물 검증 방식.
_Avoid_: 피드백 루프, 리뷰

**도메인 정의서**:
문제 영역의 용어·규칙·경계를 정리해 "무엇을, 왜"를 고정하는 기준 문서.

**PRD**:
도메인 정의서에 "어떻게, 언제"를 더한 제품 요구사항 문서로, 이후 설계와 개발의 기준점이 된다.
_Avoid_: 기획서, 요구사항 정의서
